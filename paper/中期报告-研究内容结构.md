# 中期报告研究内容结构（C 方案）

> 本文档是中期报告、开题报告修订、后续论文写作的**单一事实源**。  
> 核心结论：RQ1 不是某一个研究点，而是两个研究点的共同建模语言；点一取“空间切分 + 卸载”，点二取“流程切分 + 上下文共享 + 分层决策”。

---

## 0. 一句话定位

> **点一解决“任务间”的资源竞争，点二解决“任务内”的协同推理；HRL 是点二的求解器，不是与点一并列的问题。**

对应开题报告原话：

> 研究点一将解决“任务间”资源竞争问题，为研究点二中宏观任务的分解与调度提供了价值评估的依据；而研究点二将实现的“任务内”深度协同，是研究点一所做智能卸载决策在复杂任务场景下的必然深化与效能保障。

## 1. 为什么采用 C 方案

| 结构 | 点一 | 点二 | 优点 | 风险 |
|---|---|---|---|---|
| A：问题递进 | 论文：单模型、空间切分、卸载 | RQ1：多模型、双维切分、共享、HRL | 最贴开题；论文即点一 | 点二内容偏多 |

| **C：两层递进（采用）** | 模型感知的单任务空间切分与卸载（论文 + 模型族） | 任务内协同：流程切分 + 上下文共享 + HRL | 论文仍是点一；RQ1 拆分合理；两点都有独立问题和方法 | 需要明确边界，避免重叠 |

**选择 C 的理由：**

1. 保留论文作为点一主体和整个大论文的基座；
2. 让 RQ1 的“通信换精度”和“双维切分”在点二有完整落点；
3. 两个研究点的问题不同：点一是“任务间资源竞争”，点二是“任务内深度协同”；
4. 与开题报告的原始逻辑一致，中期解释成本最低。

## 2. 点一与点二的边界

### 2.1 点一：模型感知的单任务空间切分与卸载

**一句话**：一张遥感大图 = 一个任务；决定切多大 tile、每个 tile 卸载到哪；在 deadline 约束下最大化 mIoU。

**包含：**

- 系统架构：LEO 遥感 + MEO 编排 + LEO 计算 + 地面云；
- 任务模型：单任务、单模型（DeepLabV3+ 或模型族中的固定一档）；
- 空间切分：tile 尺寸 τ、overlap o；
- 卸载：每个 tile 分配到 MEO / LEO / 地面站；
- 目标：deadline 硬约束 + mIoU 最大化；
- 算法：A2C 在线探索 + DT 离线蒸馏；
- 证据：WCNC 论文 + 仿真器 + 实验。

**代码状态（2026-10）**：`simulator/` 已完成点一实现并验证：模型感知代价（`ModelProfile`）、空间切分 `(τ, overlap)`、raw-image 初始跳、MEO 本地处理、地面站队列、A2C/PPO 变量长策略（`SlicingOffloadPolicy`）、DT 离线训练与评估；20 项单元测试通过，A2C/PPO/DT 端到端 smoke test 通过。

**边界：不做流程切分，不做跨星上下文共享。**

### 2.2 点二：任务内协同的流程切分、上下文共享与分层决策

**一句话**：一个复杂任务 = 一条模型管线/子任务图；决定用哪个模型、在哪切管线、是否跨星共享上下文、子任务怎么分配；用 HRL 求解。

**包含：**

- 模型族：small / medium / large；
- 流程切分：cut_pt ∈ {0,1,2}，解决大模型内存不可行；
- 上下文共享：L1 边界特征、L2 全局摘要，通信换精度；
- 目标：多目标 (T, E, mIoU)，或 deadline 硬约束 + mIoU + 能耗软约束；
- 算法：Manager-Worker HRL（高层选分解方案，低层做资源分配）；
- DAG 建模：tile 图 + 管线图；
- 证据：RQ1 建模 + 仿真器扩展 + 初步实验。

**代码状态（2026-10，MVP）**：已落地 `model_family`（small/medium/large）、节点内存过滤、`cut_pt ∈ {0,1,2}`、L1/L2 共享 surrogate、简化能耗模型，以及 Manager-Worker HRL 的 `--point2` 接入；可行策略展平为 112 个动作索引；点二单元测试与 A2C/PPO/HRL smoke 实验通过。下一步补真实共享标定与更大规模训练。

**边界：不重复点一的单模型卸载，而是在点一的模型感知表征上，增加“任务内”的切分与共享。**

### 2.3 两者的关系

```
点一：任务间资源竞争
  一张图 → 切成 tile → 每个 tile 卸载到哪
  单模型、空间切分、A2C+DT
        │
        │ 继承：系统模型、MDP、仿真器、mIoU 目标、模型感知表征
        ▼
点二：任务内深度协同
  一条管线 → 选模型 → 在哪切 → 是否共享 → 子任务怎么分配
  多模型、流程切分、上下文共享、HRL
```

### 4.2 需要主动说明的五处调整

**（1）VOI 的操作化**

- 原文：引入信息价值作为核心评估准则，优化任务最终效能。
- 建议表述：定义任务效用 `U_m = V_m · Q_m`；`V_m` 为任务级信息价值（时效性、区域语义重要性、稀缺性），`Q_m` 为可测处理质量（mIoU 为代理）。单任务阶段令 `V_m` 为常数，与论文一致；复杂任务阶段用 `V_m` 刻画 tile/区域级优先级。
- 理由：论文实际优化 mIoU，直接说 VOI 会被追问“怎么算”。

**（2）DAG + Option-Critic 的具体化**

- 原文：使用 DAG 精确建模复杂任务，基于 Option-Critic 的分层强化学习。
- 建议表述：两级 DAG——粗粒度 tile 图（节点 tile，边为空间邻接/共享关系）+ 细粒度管线图（节点 Backbone/ASPP/Decoder，边为数据依赖）。高层选任务分解方案与优化偏好，低层做子任务映射与执行顺序。实现采用 Manager-Worker 时间抽象，与 Option-Critic 的 option 思想一致但训练复杂度更低。
- 理由：RQ1 的双维切分天然是两级 DAG；Manager-Worker 已有原型。

**（3）环拓扑与同构星座**

- 原文：K 颗同构卫星、同一轨道面、静态环拓扑。
- 建议表述：保留真实星座的物理可见性与链路预算；协同图定义为计算节点上的 k-近邻逻辑图（k=2 对应环，k=6 对应论文的 6 条 ISL）。环模型作为理论分析特例，仿真器使用真实 TLE 与可见性图。
- 理由：兼顾解析可处理性与实验真实性。

**（4）MARL 的定位**

- 建议表述：基座阶段采用 MEO 集中式编排（单智能体、多节点动作），与论文一致；复杂任务阶段计划扩展为 CTDE-MARL（每个 LEO 为智能体、集中式评论家）。中期报告区分“已实现的集中式分层决策”与“计划中的多智能体扩展”。

**（5）能耗与内存**

- 建议表述：加入简化能耗模型 `E = P_tx·t_tx + P_comp·t_comp + P_idle·t_queue`；模型族表加入参数内存与激活内存，按 tile 尺寸和切分点计算；动作空间加入可行性掩码。
- 理由：这是“大模型必须切分”和“能耗约束”的物理基础。
